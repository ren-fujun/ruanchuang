# PDF 优先：接口补充与交接（候选版，待 A/B/D 会签）

## 1. 已确认的决策

2026-11-08，用户确认：PDF 优先、暂无源码、从零创建桌面教师工作台。本文件描述本次实现的具体对接方式，不声称修改了原始 PDF，也不代表其他团队成员已接受补充定义。

| 冲突 | 本次采用 |
| --- | --- |
| 工单 ID / 内容 / 风险 | ticketId / content / riskLevel |
| 状态 | PDF 大写枚举，CONFIRMED 与 ARCHIVED 分开 |
| 角色 | COUNSELOR；真实后端必须从 token 解析身份 |
| 分派 | deptId + handlerId + remark + slaHours；单部门，复合需求拆分 |
| 响应 | {code:0,msg:"success",data:...}；错误业务码与 HTTP 采用 PDF 的 400/401/403/404/409/422/500 |
| 分页 | {list,total,page,pageSize}，默认 10 |
| 空值 / 时间 | 缺失标量为 null，集合为空数组；ISO 8601（本实现输出 UTC Z，展示 Asia/Shanghai） |
| 部门操作 | 教师不代录接单、不提交部门反馈，不通过接口改变其他角色状态 |
| 附件 | URL 数组；教师只读，不实现上传端 |
| 刷新 | 30 秒轮询 + 手动刷新；写操作后立即重取详情 |

SELF_RESOLVED 不作为正式工单显示。REJECTED 在教师端显示“待重新分派”，学生端由 B 按 PDF 显示“辅导员协调中”。风险说明仅在教师详情展示，真实后端必须对其他角色过滤。

## 2. PDF 已有路径，但响应/请求缺失细节的候选补全

完整 TypeScript 结构见 `src/types.ts`，候选 OpenAPI 见 `docs/openapi.json`。A 确认前不要宣布真实联调通过。

| 方法 / 路径（均在 /api 下） | 本次采用的 data / 请求 |
| --- | --- |
| POST /auth/login | 请求 {account,password}；返回 {token,user} |
| GET /auth/me | data 直接为 User：userId,name,role,college,scope |
| GET /dicts/responsibility | {departments,categories}；部门包括 deptId,name,short,slaHours,handlers[{handlerId,name}] |
| GET /counselor/dashboard | Dashboard：stats、trend、priority、departments、categories、risks；首页与洞察复用一个聚合接口 |
| POST /counselor/tickets/{ticketId}/review | {approved:boolean,remark:string}；通过后 reviewed=true，仍为 PENDING_REVIEW 等待分派；退回进入 DRAFT，原因必填 |
| POST /counselor/tickets/{ticketId}/assign | PDF 原字段；返回完整 Ticket，清除驳回原因，状态 ASSIGNED；只允许已审核待分派或 REJECTED |
| POST /counselor/tickets/{ticketId}/split | {children:[{title,content,deptId}]}；2–5 条、标题不同且最多 40 字；返回父 Ticket；子工单 ASSIGNED，继承学生/风险/附件，独立时限；父状态保留，禁止再次拆分 |
| POST /counselor/tickets/{ticketId}/urge | {remark}，必填；不改变状态，记录 WARN（按 PDF 接口表）；仅 ASSIGNED/PROCESSING |

**上述审核的中间状态、拆分后的初始状态与默认经办人均为待会签行为。** PDF 没有定义审核通过与分派之间的状态，也没有定义子项字段；本实现采用 reviewed 辅助字段和部门默认经办人，不能据此要求已有后端随意改变状态机。

PDF 定义 `/counselor/tickets/pending`。本实现使用下方建议的统一列表接口并传 `status=PENDING_REVIEW`，以支持 C 的全状态筛选。如果 A 仅提供 pending 路径，可在 api.ts 为待审核场景适配，但仍需提供其他状态的列表能力。

## 3. C 功能需要、PDF 未列出的候选接口

| 方法 / 路径 | 含义与约束 |
| --- | --- |
| GET /counselor/tickets | q（标题/编号/学生名）、status（逗号状态）、riskLevel、isOverdue、page、pageSize；提交时间倒序；上限 50；仅授权范围 |
| GET /counselor/tickets/{ticketId} | 完整 Ticket、日志、备注、子单 ID、操作权限；不存在 404，越权 403 |
| POST /counselor/tickets/{ticketId}/notes | {text}，1–1000 字；DRAFT/ARCHIVED 不可写；内部可见 |
| POST /counselor/tickets/{ticketId}/remind-confirm | {}；仅 PENDING_CONFIRM；只发送通知、记日志，不改变状态 |
| POST /counselor/tickets/{ticketId}/archive | {}；CONFIRMED 或全部子项 CONFIRMED/ARCHIVED 时可用；归档后只读 |

Ticket 展示扩展：studentName、college、reviewed、suggestedDeptIds、logs（PDF TicketLog）、notes、solution、rejectReason、children、permissions。所有操作按钮只读取 permissions；没有权限字段不会默认放行。新增日志 action NOTE / REMIND 也是候选扩展，需 A 确认或映射至团队统一日志定义。

SLA 本地只做分派表单的预计截止预览。真实 SLA、超时等级、权限、聚合统计必须服务端计算；页面不以本地推算覆盖 isOverdue 等字段。

## 4. 聚合口径

- 所有工单均限定当前辅导员授权范围；含父单与子单，每条正式工单计一次。若团队希望父单不计数，需要统一调整后端口径。
- pending：PENDING_REVIEW；active：ASSIGNED/PROCESSING；completed：CONFIRMED/ARCHIVED。
- overdue：服务端 isOverdue=true；PENDING_CONFIRM/CONFIRMED/ARCHIVED/DRAFT 不计超时。
- highRisk：首页计未办结的 HIGH；洞察风险分布计全部正式工单。
- trend：近 7 个上海自然日；按 createdAt 统计新增、按实际确认办结时间统计办结。Mock 用已办结记录 updatedAt 演示，真实后端须用不可变的确认日志时间，不能在归档后重复算办结。
- 部门效率：按服务端承办归属统计；无已办结样本返回 null；真实按时率按确认/部门完成哪个时间点计算仍需 A 确认。Mock 按 updatedAt 与 slaDeadline 演示，不作为真实 SLA 规则来源。

## 5. 错误与测试边界

401 受保护接口触发统一 auth-expired 并清 token；登录失败保持登录表单。403 显示无权访问、不清 token；404 显示错误与返回列表入口；409 刷新详情，保留输入且不盲目重试；422 保留表单展示原因；网络失败/超时可重试；提交期间禁用按钮。

当前本地 Mock 有请求 token 校验、角色固定 COUNSELOR、动作权限及基本入参校验。**这不是安全后端**：账号、状态和数据由浏览器模拟，无法证明真实 RBAC。学生创建 → 部门反馈 → 学生确认的跨端 E2E 必须等 A/B 的真实实现才可验证。

D 可通过 X-Mock-Scenario: empty 检查列表空态、error 检查 500；测试也覆盖 401/403/404/409 与小屏溢出。提醒/催办只记 Mock 日志，真实消息投递由 A 对接学生端。
