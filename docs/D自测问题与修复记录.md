# D 自测问题与修复记录

日期：2026-11-25。范围为本地真实浏览器和 API 自测，不包含尚未部署的公网环境。

## 问题 1：反馈缺少试用统计字段

- 现象：反馈表只采集类型、评分和描述，无法直接得到任务是否完成与耗时。
- 修复：增加“任务是否完成（已完成/部分完成/未完成）”和“完成耗时（1—240 分钟）”。
- 服务端：校验并持久化 `taskCompleted`、`durationMinutes`，管理员反馈列表可读取。
- 验证：`node scripts/c/feedback-e2e.mjs` 和 `server/trial-auth-api.test.js` 通过。

## 问题 2：非试用模式显示无效反馈按钮

- 现象：本地非试用环境仍显示“试用反馈”，提交后返回“试用反馈未启用”。
- 修复：新增 `GET /api/trial/status`，前端仅在试用功能启用时显示入口。
- 验证：非试用演示彩排不再出现无效反馈入口；试用模式五端反馈 E2E 仍通过。

## 问题 3：导师/教务端反馈状态权限错误

- 现象：导师和教务会话请求 `/api/trial/status` 被角色中间件拦截，导致反馈入口不显示。
- 修复：将该只读状态接口加入导师/教务允许路径。
- 验证：五端反馈 E2E 中五个角色全部通过。

## 问题 4：测试随机端口偶发失败

- 现象：自动测试偶尔分配到浏览器禁止端口 `2049`，导致页面无法打开。
- 修复：测试动态端口限制为 `10000` 以上。
- 验证：C 报修、反馈、五端、D 后勤和演示彩排脚本均重新运行通过。

## 问题 5：学生报修未进入首页统计和正在跟进

- 现象：学生提交直达后勤报修后，首页“我的诉求/正在跟进”只统计旧工单，用户会误以为报修没有提交成功。
- 修复：学生首页合并读取 `/api/repairs`，把未结束报修加入总数与正在跟进，并在列表中直接链接报修详情。
- 验证：实际提交后“我的诉求”和“正在跟进”均增加 1，报修出现在首页及“我的报修”列表。

## 问题 6：报修详情缺少下一步说明

- 现象：详情页只显示“待后勤分配”等状态，没有告诉学生当前是否需要操作。
- 修复：按 7 个状态增加“下一步”提示，说明等待领取、处理方式、满意确认、一次异议和协调结案等行为。
- 验证：真实浏览器提交后，详情页能显示状态和下一步指引。

## 问题 7：报修地点完全依赖手填

- 现象：学生必须自己输入完整地点，容易写错楼栋、房间或格式不一致，也不利于后勤责任范围匹配。
- 修复：新增服务端地点字典，学生按“校区 A—F → 1—30栋 → 1—20室”三级下拉选择提交；服务端再次校验校区、楼栋和房间组合。
- 验证：C 跨端 E2E 和 D 后勤 E2E 均使用结构化地点通过。

## 问题 8：待接单没有预计时间

- 现象：提交后只显示“待后勤分配”，学生不知道需要等多久，容易反复刷新。
- 修复：报修创建时写入预计接单截止时间，默认 30 分钟，可由 `REPAIR_CLAIM_MINUTES` 配置；学生可在报修详情看到剩余分钟和最晚接单时间。
- 验证：创建接口返回 `claimDueAt`，详情页显示预计接单提示。
