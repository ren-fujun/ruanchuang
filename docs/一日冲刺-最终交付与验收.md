# 一日冲刺最终交付与验收

2026-11-27，在2254f53基础上继续实现。代码尚未上传或部署；使用单进程JSON原型和隔离虚构数据。

## 完成的代码

- 学生最多选择同一辅导员的两个意向窗口，七日横滑视图展示未开放、可申请、满额可候补。预计时长可修改，老师私人安排不对学生展示。
- 排班按教师确认的办理期限、历史候补、申请时间排序；按5分钟找连续空档，检查教师及学生的跨窗口时间冲突。取消后尝试候补补位，其他已确认预约不移动。
- 创建幂等，同请求标识不同内容409；取消、期限、帮扶结果使用版本校验。只允许负责学生范围内操作，新增符合现有结构的站内通知。
- 预约双向留言、未读数、发送者、刷新与持久化；教师记录帮扶结果，学生查看。学业支持可带课程名称跳到预约。
- 修正建议接口重复/api、否定句、口语及话题切换，混合事务保留人工选择。建议仅在短且未命中规则时按APPOINTMENT_ADVICE_LLM=true尝试模型，敏感标记不送模型；失败或格式错误回退。AI晚返回不会覆盖学生手动修改。

## 复现

- `npm run test:appointments`
- `npm run test:appointments:e2e`：真实API与重启；加`-- --ui`进行手机/教师浏览器验收及录屏。
- 浏览器需Playwright和Edge，录屏需Playwright ffmpeg。可将PLAYWRIGHT_BROWSERS_PATH设置到项目.tmp/playwright并运行`node node_modules/playwright/cli.js install ffmpeg`。
- 使用虚构账号和独立数据启动API、学生端和辅导员端，学生提交、老师排班、双方留言、老师记录结果、学生核对。

## 需要真实参与者或外部条件

教师对优先级、时长、到课申诉归属及跨学院职责的确认；图书馆/电费官方渠道核实；3–5名真实同学体验；90秒答辩视频剪辑；账户价格和账单核对。未以模拟结果代替这些事项。

私人课表/日历接入、个人课程冲突、真实校务同步、多实例数据库并发和公网生产部署未验证。当前以老师主动发布接待窗口为准，试行排班策略仍需老师确认。
