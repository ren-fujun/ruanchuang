# 教师端 v1 接入迁移清单

更新时间：2026-11-10。依据分支 `feat/teacher-ui-v1` 与当前 v1 合同的只读核对结果编写。

## 结论

教师端分支来自独立 Git 历史，不能直接合并进主仓库；其页面可以迁移，但接口、类型和状态必须先适配 v1。本清单不改变 v1 现有业务含义。

## 可迁移内容

| 内容 | 处理方式 | 负责人 |
| --- | --- | --- |
| 教师端页面布局、图表表现、交互文案 | 逐文件迁移到 `src/pages/counselor/`，复用主仓库 `src/lib/api.ts` 与 `src/types.ts` | C |
| 纯展示组件与样式 | 与 B 的共享 UI 对齐后迁移，避免新增第二套组件库 | B + C |
| Mock 场景与页面测试思路 | 改成 v1 envelope、字段与状态后纳入现有 MSW/E2E | D |

## 必须适配的协议差异

| C 候选协议 | v1 唯一协议 | 处理结论 |
| --- | --- | --- |
| `ticketId` | `id` | 必须改名 |
| `content` | `description` | 必须改名 |
| `riskLevel` | `risk` | 必须改名并使用 `low/medium/high` |
| `PENDING_CONFIRM`、`CONFIRMED`、`ARCHIVED` | `pending_review`、`assigned`、`processing`、`awaiting_confirm`、`completed` | **待确认**；不得自行映射或新增归档状态 |
| `/counselor/tickets/:id/assign` | `PATCH /api/tickets/:id/review` | 必须改为 v1 路径与 `departmentIds` 入参 |
| `/notes`、`/archive` 等候选动作 | `POST /api/tickets/:id/note` 等 v1 已定义动作 | `archive` **待确认**；其余按 v1 路径迁移 |

## 合入顺序

1. C 从最新 `main` 新建 `feat/c-teacher-v1-adapter`，不直接合并旧教师端分支。
2. C 先替换 API 调用与类型，再迁移页面；禁止在页面内维护第二套接口类型。
3. A 审核字段、路径、状态机；B 审核共享组件；D 把场景加入 E2E。
4. 对“归档”“退回审核”等 v1 未定义能力，由 A/B/C/D 会签后再写入合同、OpenAPI、类型与后端。
