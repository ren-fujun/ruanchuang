## 合并状态

- `server/index.js` 存在一处内容冲突：A 分支新增问题包与后勤接口，C 分支新增 B 路由挂载。
- 在预检分支中保留双方代码后，类型检查通过。
- 五端独立构建全部通过。
- D 的后勤端到端测试七项全部通过。
- C 自带浏览器验收在当前合并结果上未通过，辅导员问题包表单会在页面刷新时被替换。

## 已确认可用

A 后端与 D 后勤端已经走通以下闭环：

1. 辅导员创建问题包草稿。
2. 辅导员指定 `recipientId` 转交。
3. 指定后勤账号只读取自己的事项。
4. 后勤逐项接收并填写处理结果。
5. 单条结果进入学生待确认，其他事项保持独立。
6. 学生反馈未解决后，辅导员可重新转交并由后勤再次办理。
7. 学生确认后原工单办结，不连带关闭同包其他事项。

验证覆盖其他后勤账号拒绝操作、后勤身份拒绝进入辅导员看板，以及 390px 手机宽度无横向溢出。

## 仍未接通

C 页面当前仍按自己的提案契约调用接口，与 A 已实现契约不一致：

| 动作 | C 当前使用 | A 当前实现 |
| --- | --- | --- |
| 查询问题包列表 | `data.items` | `{ bundles }` |
| 创建问题包 | `data.item`，提交 `title/departmentId/reviewed/requestId` | `{ bundle }`，提交 `ticketIds/note` |
| 查询问题包详情 | `GET /issue-bundles/:id` | 尚未实现 |
| 转交问题包 | `POST /issue-bundles/:id/send` | `POST /issue-bundles/:id/dispatch`，要求 `recipientId` |
| 学生重开 | 提案字段 `text` | 已实现字段 `reason` |

因此不能把两个分支直接合并后宣称问题包全链路已完成。D 后勤端已经可以独立验收，但辅导员页面还无法通过真实 A 接口稳定创建、查看并转交问题包。
