# AI 深化与评分验收映射

## 范围与原则

围绕现有“综测咨询 → 预约 → 老师摘要 → 结果整理”深化，不新增业务模块。评分依据为正式 PDF《主题软件定义世界 创新引领未来》：先过可行性门槛并核实原创差异，再按创新 40 分、技术 25 分、价值与社会效益 20 分、工程 15 分准备证据。本表用于指导验证与留证，**不预测或宣称已获得任何分数**。

当前来源只核实了综测细则的 1 个审核片段；完整细则、适用范围和版本仍待核验。Docker 已安装但需重启/检查 WSL，百炼 Key 尚未配置，真实向量入库与云端评测未运行。不得把待办、合成数据或离线规则结果描述成真实用户效果。

## 可执行验证计划

### 1. 合成题与人工审核（60 道，20 道开发、40 道测试）

沿用 `scripts/ai/rag-cases.mjs` 中60道固定合成咨询题，20道用于开发、40道用于测试。测试运行前由人工核对预期和适用资料并冻结版本；不得运行后迎合模型改变答案。预约草稿、摘要确认、结果整理、越权与检索故障另由接口及浏览器回归覆盖，不混算为60道真实模型题的成绩。每题留存输入、输出、引用、预期、判定和缺陷。

人工逐题检查答案正确性、引用支持性、适用范围及应否追问或转人工。记录审核者、日期和逐题意见；目标为可回答题正确率≥90%、引用主张支持率≥95%，均为待检验指标。自动结构检查不代替人工判分。

### 2. 配对任务可用性观察

招募 1 位老师和 5 位学生，完成相同的咨询到预约/摘要配对任务；在参与者间交替任务顺序，避免固定顺序带来的练习偏差。记录每位参与者两种流程的任务用时、成功与否、摘要修订次数及主要障碍，报告中位数与逐人差异。目标是新流程中位用时降低 30%；该数值是待检验目标，不是已取得结果。样本很小，只能作为探索性可用性观察，不能外推总体成效。

### 3. 环境与向量链路

先执行环境采集脚本并留存硬件信息，再在 Docker Desktop/WSL 可用、百炼凭据由本机安全配置后检查 Qdrant、实际向量入库和检索。记录模型、数据版本、运行日期、错误与成本。不要把密钥写入报告、命令输出或仓库。当前真实向量和云评测均未运行。

## 验收记录模板

每次运行记录：日期与代码版本、任务编号、数据类型（合成/真实且经授权）、执行步骤、预期、实际输出、引用证据、耗时、硬件、审核人、缺陷及复测状态。未做的检查写“未运行”；没有证据的项目写“待核验”。

## 本轮实现边界与复现

- 咨询在会话内保存带轮次的原话事实，模型提取的事实必须在对应学生输入中逐字存在；预约保存学生确认文本与服务端引用、材料、问题的快照。快照不是完整的编辑历史。
- 办理步骤和材料来自通过现有引用及硬事实校验的主张；引用语义是否充分支持仍须人工审核。没有审核通过的依据不会输出材料要求。
- 结果整理接口为 `POST /api/appointments/:id/outcome-draft`，输入 `{notes,version}`，返回 `{item:{draft,engine,reason}}`。仅所属辅导员对已排班预约可调用，不改变预约状态。老师以分号或换行划分要点，模型仅输出完整索引排列，程序保留原话、添加编号，避免生成未经输入的新结论；少于两条要点保留原文。该能力是受约束的要点组织，不是自由改写。
- 老师确认后仍调用原完成接口；等待期间的编辑和状态变化会使旧草稿失效。模型失败保留输入，调用用量进入既有记录，单价缺失时费用为未知。
- 运行 `npm run test:rag`、`npm run test:rag:ui`、`npm run typecheck` 和现有排班回归。浏览器验证的咨询与老师草稿响应明确使用合成替身，不代表真实模型质量。
- 三组真实评测沿用 `node scripts/ai/eval-rag.mjs --live --split test --limit 40`；当前前置条件未满足，未运行。配置完成前不发布AI正确率和省时比例。

## 后续一致性加固

- 更正话题保存有效起始轮次；之后模型提取到被替代轮次的原话时拒绝带回摘要，同轮重复片段不重复写入交接文本。
- 预约创建增加可选 `consultationTurn`；新前端带入草稿对应轮次，服务端拒绝过期轮次的新申请。旧客户端不传该字段时沿用原行为；已有申请的相同请求允许幂等重试，轮次不同的请求拒绝复用标识。
- 反馈接口增加可选 `turn`，缺省仍为最新轮；按会话与轮次更新，防止旧回答反馈记到最新轮、重复点击被累计。
- 后续加固验证：35项针对性测试、TypeScript与390/412宽度浏览器回归通过。咨询与老师草稿仍用明确标记的替身验证界面，真实模型未调用。
