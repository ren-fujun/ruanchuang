# 五端独立开发方案与四人分工

版本：2026-11-14；口径：学生、辅导员、教务处、后勤、导师。方案中的工期为估算，不是学校制度或完成承诺。

## 1. 决策与资料依据

以用户确认的五端口径为准。《五方功能需求梳理》作为页面功能清单，《学生事务AI助手五部门工作流程》补充交接材料、异常回流和闭环标准。两份资料中的“会议提出”“建议补充”“待确认”保留不同优先级，不能把建议或待确认规则当成已经获批的业务制度。

心理中心不单建第六端：保留受限的转介状态、负责人、回访要求；详细心理记录留在学校认可的专业系统。信网中心不单建第七端：其知识库、AI运行、权限、日志和部署职责进入共享平台。导师单独成端，不能把导师与辅导员视作同一种权限。

本次提供方案、分工及工程骨架，不宣称三个新增业务端已实现真实办理。

## 3. 五端范围和验收

| 端 | P0：第一条闭环 | P1：第二阶段 | P2：学校确认后 |
|---|---|---|---|
| 学生 | 提交/补充、进度、结果确认、不满意重开、消息 | 有来源的AI问答与追问、预约 | 请假、材料任务、问卷、外出反馈 |
| 辅导员 | 诉求核对、问题打包、人工转交、逐条回执、催办回访 | 学业联系待办、预约排班、知识纠错 | 会议签到、材料汇总、请假签名 |
| 后勤 | 本部门问题包接收、退回原因、经办分配、单项结果、返工 | 地点/历史检索、延期说明 | 对接现有报修系统、批量导出 |
| 教务 | 独立框架及权限契约 | 名单模板/校验、分发、更正、重修结果回写 | 真实教务系统同步、学校批准的导出 |
| 导师 | 独立框架及权限契约 | 所属学生任务、联系/面谈、重修提醒、协同与转介 | 日历及学校认可的外部通知 |

生活闭环验收：学生提交两条问题 → 辅导员打包核对 → 后勤明确接收 → 分别记录结果 → 学生逐条确认；其中一条不满意重开，不得把整个问题包自动标记全部完成。

学业闭环验收：教务导入并校验名单 → 正确导师和辅导员分别收到任务 → 联系、面谈、重修提醒 → 教务回写通过/未通过 → 通过结束、未通过续跟。错误名单需要更正版本，不能直接覆盖历史。

AI验收：展示来源与有效期；无法确认则追问或转人工；分类、合并、转交和审批由有权人员确认；模型故障不能阻断提交。

## 4. 独立开发架构

采用单仓库五个前端入口、共享组件/契约、一个受权限控制的后端。这里“端口”既指五种业务端，也提供五个固定本地网络端口；不拆成五套互不兼容的数据和五份AI服务。

| 端 | 目录 | 启动命令 | 本地端口 | 独立构建产物 |
|---|---|---|---|---|
| 学生 | apps/student | npm run dev:student | 5191 | dist-portals/student |
| 辅导员 | apps/counselor | npm run dev:counselor | 5192 | dist-portals/counselor |
| 教务 | apps/academic | npm run dev:academic | 5193 | dist-portals/academic |
| 后勤 | apps/logistics | npm run dev:logistics | 5194 | dist-portals/logistics |
| 导师 | apps/mentor | npm run dev:mentor | 5195 | dist-portals/mentor |

先 `npm ci`，另开终端 `npm run dev:api`（8787）；各端可单独启动，也可以同时启动。开发代理可通过 PORTAL_API_URL 指向另一个后端。所有端构建：`npm run build:portals`；类型检查：`npm run typecheck`。固定 strictPort，端口冲突会报错而不悄悄换端口。

学生、辅导员复用已验收主应用，当前仍共享旧双角色路由和登录页；入口和构建已经独立，专属登录页及路由裁剪是下一阶段 C 的任务。不同端口的 localStorage 相互隔离，但这不构成服务端授权。

三个新增端目前各有入口、模块配置、可切换导航、空态和响应式布局，清晰标识“开发骨架预览”。它们不读取真实学生数据，不假冒登录成功，不调用现有辅导员接口。新页面分别在各自目录演进，共享外壳只负责展示。

部署时五份产物由静态服务器托管，配置 SPA fallback 和同源 /api 反向代理；当前 Express 仍只服务原 dist，不自动发布 dist-portals。正式身份认证、域名和跨端单点登录需后续设计。

## 6. A/B/C/D 四人任务分工

按新增工作量分配，而不是按五端平均切成五份。估算为净开发人日，包含自测；每人约18人日，总72人日，另留团队8人日整合缓冲。约4周是计划窗口，数据授权或外部接口延期不计入团队可控工期。A/B/C/D是建议技术角色，不表示已确认个人能力。

| 成员 | 技术角色与主责 | 工作包/估算 | 交付与验收 |
|---|---|---|---|
| A | 后端/集成负责人；教务端业务主责 | 五角色鉴权、数据范围、共享工单/问题包/附件接口10日；教务导入校验/更正/回写6日；契约和迁移2日 | 后端拒绝越权；名单重复/缺失行有错误报告；版本可追踪；教务闭环通过 |
| B | AI与学业跟进负责人；导师端主责 | 追问、来源/有效期、知识审核版本与AI评测8日；导师列表/联系/面谈/重修8日；转介和敏感摘要2日 | 导师仅见所属学生；AI无依据转人工；导师结果仅共享必要状态 |
| C | 前端体验负责人；学生端与辅导员端主责 | 学生补充/重开/预约等增量6日；辅导员问题包/回访/预约工作台9日；双端路由拆分与共享组件3日 | 已有功能不回退；问题包人工核对；桌面/手机可用；失败/空态齐全 |
| D | 后勤端与质量交付负责人 | 后勤接收/经办/单项回执/返工8日；五角色权限、API与浏览器回归6日；部署、演示数据、文档与发布4日 | 后勤不能读成绩/面谈；单项结果不误关全包；可复现安装、启动与验收 |

端主责不等于独包所有层：A维护共享API与迁移，B实现导师业务服务并由A评审，D实现后勤业务服务并由A评审，C提供共享组件但不承接所有页面。D负责测试体系，每位开发者负责自己模块单测与修复。否则A与D都会成为瓶颈。

代码边界：A主改server共享鉴权/数据及apps/academic；B主改server/ai及apps/mentor；C主改src/pages/student、src/pages/counselor、两个旧端入口；D主改apps/logistics和scripts/e2e。多人需要改server/index.js时由A统一集成，先把新业务拆成各自路由模块；避免四人长期在同一文件并行修改。

## 7. 四周顺序与依赖

第一周：A冻结身份/数据范围/接口样例；B补标准答案结构与导师任务契约；C拆双端登录路由、做问题包交互；D完善后勤骨架和权限矩阵测试。输出：五端独立启动、角色与接口边界评审。

第二周：A接通问题包与后勤状态；C完成学生补充/不满意重开及辅导员核对；D完成后勤真实办理；B完成AI追问、依据和转人工。输出：生活问题完整闭环，含退回和返工。

第三周：A教务导入/分发/更正；B导师联系/面谈/结果跟进；C辅导员学业待办与学生结果视图；D校验学业权限和异常链。输出：学业闭环，名单错误、无导师、未通过三类异常可回流。

第四周：基础预约按剩余能力推进；优先修复权限、数据一致性和既有功能回归。电子签名、短信、真实系统同步暂不承诺。D组织五角色验收与演示；A/B/C关闭各自缺陷。缓冲不足时先延期预约增强，不能删权限检查或用虚假成功提示凑功能。

## 8. 合并和验收约束

每个业务分支写清输入、动作、输出和权限，提交小PR；改共享类型由A/C一起评审。合并需类型检查、原构建、五端构建通过；涉及业务状态或权限需相应API与浏览器验证。测试对独立数据文件执行，不覆盖原演示数据。

必测：学生读别人记录403；导师读非所属学生403；后勤访问成绩/面谈403；内部备注不泄露；重复提交/重复接单不产生双记录；部分完成不关闭整个包；不满意重开保留历史；名单更正可追溯；预约并发冲突被拒；模型503时可人工提交；附件实际下载受权限控制。

学校待确认清单：五端实际使用人和数据负责人、班级/导师对应、名单可共享字段、面谈摘要范围、退回/重开权限、文件保存期限、通知渠道、心理转介制度、电子签名方式、现有教务/报修系统对接意愿。未确认项用配置或待办记录，不编造制度、电话号码、SLA或诊断结论。

## 9. 本次交付验证

类型检查、原项目构建、五个独立构建全部通过。Edge 浏览器分别打开五端：学生/辅导员登录页可加载，三个新增端可切换业务模块，在390px宽度下无横向溢出，无页面运行异常。本次未验证尚未实现的新角色登录和业务写入。共享Vite配置为每端分配独立依赖缓存，支持并行开发。
