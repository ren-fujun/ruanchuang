## 四、答辩台词（可直接照读）

### 4.1 开场定位（约 15 秒）

> 我负责 B 部分，大模型算法与认知层。一句话概括：**让 AI 在校园诉求场景里既好用、又不敢乱说**。
> 具体是三条链路：用 GraphRAG 把「谁该管这件事」查清楚，用风险筛查 Agent 把「谁需要被优先看见」找出来，
> 再用超时熔断和一整套幻觉护栏保证「模型挂了、模型胡说」都不会影响业务。

### 4.2 GraphRAG 演示（约 40 秒，边跑 `demo-graphrag.mjs` 边讲）

> 这套图谱有 70 个节点、104 条加权边：15 个部门、23 项权责事项、19 条会签规则、7 个历史卡点、6 个流程阶段。
> 关系类型包括主责、协同、触发会签、会签部门、历史卡点、升级路径、流程先后。
>
> 请看第一条样例：学生只说了一句「宿舍漏水，插排附近渗水，怕漏电」。
> 图谱检索出两项权责——宿舍设施维修和宿舍水电与用电安全，主责是宿管中心，**后勤保障处联合主办**，
> 并且因为命中「漏电」触发了**保卫处会签**，SLA 收到 60 分钟。
> 这就是创新点 2 说的三件事：路由 Agent 找对部门、意图 Agent 识别出这是**复合工单**、并且**自动触发会签**。
>
> 再往下看证据链：每一条派单结论都能追溯到「哪个部门—什么关系—哪项权责」，前端可以直接展示给学生和辅导员，
> 而不是只给一个黑盒结果。最后一条样例我特意放了句「就是有点问题，你们看着办吧」——
> 图谱宁可不派单，提示人工确认归属，也不硬猜。
>
> 最后这张表是诉求事件图谱：用工单历史给权责节点回填权重。可以看到「宿舍设施维修」4 单里 3 单超时，
> 超时率 75%，主要卡在「物资申领与备件等待」，系统直接给出改进建议「对高频备件建立楼栋周转库存，先换后补」。

### 4.3 风险预警演示（约 35 秒，边跑 `demo-risk.mjs` 边讲）

> 风险筛查 Agent 融合两路信号。第一路是文本情绪：危机、即时安全、强烈痛苦、人际冲突、焦虑五个维度，
> 一共 96 个词，还会处理程度副词、否定和标点强度。
>
> 红线有三条：命中危机或安全信号**直接高风险，不看分数**；本地规则判过高风险的**不允许被下调**；
> 出现人际冲突信号**至少中风险**——因为冲突有升级成舆情或人身安全事件的先例。
>
> 第二路是行为时序：24 小时 / 72 小时 / 7 天的提交量、夜间占比、最短间隔、同类问题重复次数、历史超时次数、
> 30 天内是否出现过高风险。请看 R-06 和 R-07：**同一句话「宿舍空调不制冷」，无异常历史是低风险，
> 24 小时内第三次提交、夜间占比 67%，就升到中风险**，SLA 从 240 分钟收到 120 分钟。
>
> 每条结论都带干预建议：动作、话术模板、触达方式、要通知哪些部门。比如危机类是 15 分钟内电话直呼，
> 同时通知心理中心、院办和保卫处。而且模型只被允许补充「情绪解读、行为解读、干预话术」三个文本字段，
> **等级和分数完全由规则算出来**——这就是幻觉可控。

### 4.4 稳定性与幻觉可控（约 30 秒，边跑 `drill-degrade.mjs` 边讲）

> 这一屏是容灾降级演练，一共 35 项检查。
>
> 第一段：**不配 API Key**，系统照样跑——引擎标识变成 local-rules，业务结论完全一致，
> 所以断网也能演示，校园网抽风也不影响学生提交诉求。
>
> 第二段：注入四种故障，超时、网络不可达、模型返回脏 JSON、上游 500。
> 每种故障都能被**准确归因**，而且业务结论和基线**零差异**——因为我们有三层降级：
> 模型不可用就用本地规则；模型输出越界就被护栏丢字段；答复里的电话、金额、时限在来源里找不到，整段回退知识库原文。
>
> 第三段：连续失败触发熔断，状态从 closed 变 open，之后直接返回降级不再打网络，复位后恢复。
>
> 第四段是幻觉护栏：捏造的电话、金额、时限，过度承诺，提示词注入残留，全部被拦截——
> 只有出现在知识库来源里的号码才放行，110、119、120 这类公益号码例外。
>
> 第五段是知识库阈值：只有高置信命中、低风险、非紧急，才允许给自助答案。
> 只写「宿舍」两个字会被短查询规则拦截，「就是有点问题」这种没有信息量的话得 0 分、直接判未命中；
> 阈值本身也是环境变量，可以按现场情况调。

### 4.5 归因结论朗读（90~120 秒环节，用真实数据）

现场执行：

```powershell
npm start
$t = (Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8787/api/auth/demo -ContentType 'application/json' -Body '{"role":"counselor"}').token
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8787/api/ai/attribution -Headers @{ Authorization = "Bearer $t" } `
  -ContentType 'application/json' -Body '{}' | ConvertTo-Json -Depth 4
```

返回里的 `headline` / `suggestion` 即朗读内容，格式为：

> 「×××是当前最集中的流程卡点：N 单中有 M 单超时（超时率 X%），主要卡在「×××」。」

卡点权重里的超时率做了**小样本收缩** `(超时单量 + 0.5) / (单量 + 2)`：只有 1 单的权责事项不会被
「100% 超时」直接顶到第一名，排序对多单流程更公平；单量 <2 的条目会带 `sampleAdequate: false`，
若它仍然排在第一，`headline` 会自动追加「（当前仅 N 单，样本量偏小，结论供参考）」，同时给出 `sampleNote` 字段。

## 五、常见提问与回答

| 提问 | 回答要点 |
| --- | --- |
| 模型会不会瞎编部门？ | 部门 id 走白名单校验，越界直接丢弃；分类枚举同理。图谱检索的部门来自 15 个部门的部门字典。 |
| 模型能不能把高风险说成低风险？ | 不能。`guardAnalysis` 里 `risk` 与 `urgency` 只允许持平或提升，降低会被记录为 `rejected`。 |
| 模型挂了会怎样？ | 三层降级自动回退，业务字段与规则链路完全一致，只在 `trace.warnings` 留痕。`local-rules` 是正常状态。 |
| 为什么风险等级不做否定衰减？ | 危机与安全维度刻意不衰减：「我没有想不开」这类表达可能是掩蔽，宁可误报也不放过；这是安全优先的取舍。 |
| 自助答复会不会乱答？ | 只有 `confident` + 低风险 + 非紧急才开放；答复里的硬事实必须来自知识库来源，否则整段回退原文。 |
| 阈值怎么调的？ | 用 `eval-b.mjs` 当回归集：先看准确率再看覆盖率，短查询、歧义、弱证据三条规则把「高分但不可信」压回 probable。 |
| 1 单 100% 超时为什么不是第一？ | 卡点权重对超时率做了小样本收缩，单量为 1 时比率被拉向 0.5，统计意义弱的事项不会霸榜；同时用 `sampleAdequate` 明确标注样本不足，避免大屏误导。 |
| 为什么不直接上向量库？ | 当前知识库只有 8 条、离线演示优先，字段加权 BM25 + 同义词足够且零依赖；接口 `searchKnowledgeDetailed` 已抽象，换向量库不影响上层。 |
| 行为特征数据从哪来？ | 全部由工单历史实时推导，不需要额外埋点；`behaviorFeatures` 也直接给 D 当特征列。 |
