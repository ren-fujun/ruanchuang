# 智汇中枢 · 4 人小组分工与备赛计划

> 适用场景：软件创新类竞赛（校赛 / 省赛 / 国赛）
> 项目定位：以辅导员为流转中枢、AI 为调度引擎的学院级学生事务协同督办平台
> 当前版本：学生手机端 + 辅导员手机端已可运行，后端工单闭环与 AI 预检已打通

---

## 一、先统一三件事

在分工之前，4 个人必须先对齐，否则后面一定反复返工。

### 1. 一句话项目定位

> **不是又一个报修表单，而是把辅导员原本靠人情协调的督办规则，做成一条可追踪、有时限、有温度的数字化路径。**

答辩时不要从“我们做了很多页面”讲起，要从“一个学生求助如何被接住”讲起。

### 2. 比赛演示主线

建议固定一条 3–4 分钟主线路，不贪多：

1. 学生提交一条“宿舍热水不稳定”的诉求，AI 自动识别类型、风险、建议部门；
2. 辅导员中枢收到待审核工单，AI 摘要 + 高风险雷达，审核后分派宿管中心与后勤保障处；
3. 辅导员催办、记录部门接单、录入处置结果；
4. 学生收到结果，确认办结并 5 星评价；
5. 辅导员洞察页显示闭环率、部门效率与诉求热点。

心理危机预警作为“第二幕”展示 20 秒即可，不要冲淡主流程。

### 3. 本期范围冻结

**必须做：** 学生提交、AI 预检、工单进度、辅导员审核分派、催办、办结确认、评价、消息、核心数据看板、权限隔离。

**本期不做：** 完整的职能部门端、复杂后台管理、真实支付、模型微调、花哨但演示用不上的功能。

**时间富余再做：** 部门只读 H5、真实附件上传、报表导出 PDF。

> 评委问“为什么没有部门端”时，统一回答：本期聚焦辅导员与学生两端，部门侧通过标准 API 与督办代录闭环，下一阶段再开放部门独立端。不要临场承诺没做的功能。

## 二、四人角色卡

> 以下用成员 A/B/C/D 表示，请按实际技能微调。原则是：**每人一个主责 + 一个副责 + 一个答辩段落**，所有人都要有可见贡献。

### 成员 A：队长 / 产品与答辩负责人

**定位：** 项目的“叙事者”和“收口人”，对最终提交物负责。

**主责：**
- 维护项目定位、用户画像、痛点证据、竞品对比；
- 定义每轮演示范围，控制需求蔓延；
- 撰写 PPT 故事线与 5 分钟讲稿；
- 组织答辩 Q&A 题库与模拟答辩；
- 对接指导老师、比赛规则、提交节点。

**副责：**
- 辅导员端产品验收：审核、分派、催办、备注、拆分是否符合真实工作流；
- 联系 2–3 位真实辅导员做一次 20 分钟访谈，留下截图/纪要。

**交付物：**
- 《项目定位与竞品分析》1 页；
- 答辩 PPT 主框架；
- 5 分钟讲稿 + 30 题 Q&A；
- 提交清单与倒排期表。

**答辩段落：** 开场 30 秒 + 价值收尾 30 秒。

**判断标准：** 不写代码也可以，但必须能回答“为什么是辅导员中枢”“为什么不是普通表单”“真实价值是什么”。

---

### 成员 B：前端与视觉体验负责人

**定位：** 让评委在 30 秒内“看懂 + 觉得好用 + 记住”。

**主责：**
- 学生端与辅导员端页面走查、细节修复、空状态/加载/错误状态；
- 统一视觉规范：色彩、字号、间距、图标、动效；
- 产出比赛用高清截图、封面图、项目 Logo/主视觉；
- 录制并剪辑演示视频（与 D 配合）；
- 保证 390px 手机与投影大屏都能正常展示。

**副责：**
- 学生端产品验收：从“不会用”的学生视角走一遍；
- 设计 1 页“交互亮点”材料：AI 预检、风险雷达、SLA 进度、无障碍/隐私提示。

**交付物：**
- 最终 UI 走查清单（0 P0/P1 问题）；
- 8–12 张高清截图；
- 3–5 分钟演示视频（1080P，含字幕）；
- PPT 视觉模板与项目主视觉。

**答辩段落：** 学生端 90 秒演示 + 交互设计亮点 30 秒。

**判断标准：** 演示过程不出现滚动错位、字体过小、数据空白、按钮点不动。

---

### 成员 C：后端与 AI 技术负责人

**定位：** 项目的“技术可信度”来源，负责把 AI 讲清楚而不是讲玄。

**主责：**
- 稳定 API、工单状态机、权限隔离、SLA 计算、通知与统计；
- AI 预检：分类、风险识别、知识库检索、DeepSeek 可选增强与本地兜底；
- 部署与演示环境：`.env`、种子数据、重置脚本、备份包；
- 架构图、数据流图、接口说明、技术亮点页；
- 安全与隐私：角色越权、敏感字段、演示数据脱敏。

**副责：**
- 设计 20 条边界测试：越权、重复提交、空数据、高风险关键词、超时工单；
- 准备“断网/无模型 Key”降级演示方案。

**交付物：**
- 可复现部署包 + README；
- 架构图 1 张、数据流图 1 张；
- 技术亮点 1 页：AI 风控 + RAG + SLA + RBAC；
- 接口/测试说明。

**答辩段落：** 技术架构 60 秒 + AI 风控与可解释性 30 秒。

**判断标准：** 能现场解释“AI 为什么这么判”“模型挂了怎么办”“数据权限怎么隔离”。

---

### 成员 D：测试、数据与材料统筹负责人

**定位：** 让项目“经得起问”，也让全组“交得出去”。

**主责：**
- 编写测试用例与验收清单，维护 bug 看板；
- 组织 5–10 名学生 + 1–2 名辅导员做小范围试用，收集反馈；
- 维护演示数据：账号、工单、通知、统计口径；
- 汇总用户手册、测试报告、应用成效页；
- 管理提交材料命名、版本、网盘/邮件/系统上传。

**副责：**
- 答辩现场演示保障：设备、账号、备份视频、热点；
- 记录每次彩排问题，形成“最后一公里”清单；
- 负责比赛报名信息、承诺书、知识产权等行政材料。

**交付物：**
- 测试报告（功能 + 权限 + 兼容性 + 异常）；
- 5–10 人试用反馈汇总（含 3 条可引用原话）；
- 用户手册 / 演示脚本；
- 提交材料总目录与最终校验表。

**答辩段落：** 测试与应用成效 45 秒 + 现场演示保障。

**判断标准：** 任何材料能在 30 秒内找到；任何演示故障有 Plan B。

## 三、RACI：谁拍板、谁执行、谁被咨询

> R = 负责执行，A = 最终拍板，C = 需要咨询，I = 知会

| 工作项 | A 队长 | B 前端 | C 后端/AI | D 测试/材料 |
| --- | --- | --- | --- | --- |
| 项目定位与范围 | **A/R** | C | C | I |
| 学生端体验 | C | **A/R** | C | C |
| 辅导员端流程 | **A/R** | C | C | C |
| 前端实现与视觉 | I | **A/R** | C | I |
| 后端与 AI | I | C | **A/R** | C |
| 测试与缺陷收敛 | I | C | C | **A/R** |
| 演示视频 | A | **R** | C | **A/R** |
| PPT 与讲稿 | **A/R** | C | C | C |
| 答辩 Q&A | **A/R** | C | C | C |
| 提交材料 | **A** | I | I | **R** |
| 现场演示 | **A** | R | R | **R** |

**避免两种失败：**
1. 队长一个人做 PPT，其他三人“等技术做完再说”；
2. 四个人都改代码，没人对材料、视频、提交节点负责。

## 六、3 分钟答辩脚本（可直接拆分）

### 0:00–0:30 开场（A）

> 各位评委好，我们是智汇中枢团队。高校里学生诉求并不少，但真正难的是：一条诉求从学生发出，到辅导员协调多个部门解决，中间靠的是私聊、电话和人情的反复催办。我们做的不是又一个报修表单，而是把辅导员已有的督办规则，变成一条可追踪、有时限、有温度的数字化路径。

### 0:30–1:40 学生端（B）

> 学生打开手机，只需描述发生了什么。AI 会先做三件事：判断类型、识别风险、检索校园知识库。能自助解决的，直接给步骤；需要人工的，生成标准化工单。提交后，学生可以看到每一步是谁在处理、还剩多少时限，也可以温和催办。这里我们特意没有做“冷冰冰的进度条”，而是把“谁在帮你”放在最显眼的位置。

### 1:40–2:25 辅导员端（A/C）

> 辅导员收到的不是一段聊天记录，而是一张 AI 已整理好的工单：摘要、风险等级、建议部门、建议首响话术。高风险会进入雷达区，触发优先提醒。辅导员可以多部门分派、催办、记录部门接单与处置结果。所有动作留痕，超时自动升级。我们把“人情协调”变成“规则协同”，但没有增加辅导员的行政权力，只是让既有督办规则可执行。

### 2:25–2:50 技术与数据（C/D）

> 技术侧，前端是移动优先的 React 应用；后端提供工单状态机、RBAC、SLA 与通知；AI 采用本地规则 + 知识库检索，并支持 DeepSeek 增强，模型不可用时自动降级，风险等级只升不降。我们做了权限隔离与异常测试，学生只能看到自己的工单。小范围试用中，学生最认可的是“知道进度”，辅导员最认可的是“不用反复接电话”。

### 2:50–3:10 收尾（A）

> 对学校，这是一套轻量、可复制的学院级协同督办工具；对学生，每一次求助都有回响；对辅导员，是把时间还给思政主业。谢谢大家。

## 八、协作机制

### 每日 15 分钟站会

每人只回答三个问题：
1. 昨天完成了什么？
2. 今天最重要的一件事是什么？
3. 现在卡在哪里？

### 版本与分支
