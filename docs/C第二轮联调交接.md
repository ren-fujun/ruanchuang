# C 第二轮联调交接

基线 feat/d-logistics-workbench 740cb73（包含 A、B、C 和 D 已有集成），本地分支 feat/c-trial-workbench。

学生从「宿舍报修」进入直达后勤表单，报修列表及详情读取 /api/repairs；结果待反馈时可选择满意或提交一次异议。辅导员桌面报修监督可筛选、查看双方记录、提醒和在服务端允许的状态下协调结案。辅导员首页展示待审批请假、报修异议、异议回应超时及待协商学业任务；非报修旧工单仍使用原有工作流。新版报修通过 repairId 进入独立流程，旧问题包入口从导航移除。

复用 B 的请假页面和学业协商组件。共享反馈组件由各端已登录会话调用 /api/trial/feedback，显示试用提示。学生、辅导员试用账号首次登录时可修改初始密码。旧未接入预约入口从界面导航移除。

独立临时数据验收：
- node scripts/c/trial-e2e.mjs：学生提交真实报修、后勤 API 接单和处置、学生页面异议、辅导员页面协调结案，以及学生本科请假和辅导员页面审批。
- node scripts/c/feedback-e2e.mjs：五个独立端、各自会话调用真实试用反馈接口及无横向溢出。
- node scripts/e2e/logistics-workflow.mjs：后勤状态、范围、并发领取、一次异议和终态。
- npm run test:b-trial：本科/研究生审批范围和学业协商业务测试。

上述回归使用虚构数据和隔离本地服务，不等于公网试用验收。公网 HTTPS、真实邀请账号、五端统一部署和备份仍由 A/D 集成验收；需要团队确认后勤一次回应和辅导员协调结案的业务规则。
