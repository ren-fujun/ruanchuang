## 切换真实后端

复制：

```bash
copy .env.local.example .env.local
```

将 `.env.local` 改为：

```env
VITE_API_BASE_URL=/api
VITE_USE_MOCK=false
```

重启 Vite：

```bash
npm run dev:web
```

真实模式下：

- MSW 不启动；
- `/api/*` 经 Vite 代理到 `http://127.0.0.1:8787`；
- 页面使用 localStorage 中已有的 `zhihui_token`；
- 如果没登录，页面显示 `40101 / 需要登录`；
- 如果后端尚未完成 v1 envelope，页面显示 `50001 / 接口未按 v1 返回`，这是预期的迁移门槛。

## health 是什么

`GET /api/health` 是**存活检查**：

- 不需要登录；
- 不查业务数据；
- 只证明三件事：路由存在、服务在跑、返回结构正确；
- 联调第一个接口必须是它，不能先查工单。

当前 `8787` 返回：

```json
{
  "ok": true,
  "service": "智汇中枢 API",
  "time": "2026-11-07T13:17:40.738Z"
}
```

这是 v0，**不算 v1 通过**。

目标：

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "ok": true,
    "service": "智汇中枢 API",
    "time": "2026-11-08T10:00:00.000Z"
  }
}
```

## health 怎么通

后端 A 改 `server/index.js`，加两个 helper：

```js
const ok = (res, data, msg = 'ok') => res.json({ code: 0, msg, data })

const fail = (res, status, code, msg) =>
  res.status(status).json({ code, msg, data: null })
```

把 health 改成：

```js
app.get('/api/health', (req, res) => {
  ok(res, {
    ok: true,
    service: '智汇中枢 API',
    time: new Date().toISOString(),
  })
})
```

验证：

```bash
curl -s http://127.0.0.1:8787/api/health
```

通过标准：

- HTTP 200
- `code === 0`
- `data.ok === true`
- `data.time` 是 `...Z` 字符串
- 响应 < 500ms

时间节点：

- 2026-11-09 18:00 前：A 完成 v1 health；
- 2026-11-10 10:00：联调第一项必须通过；
- 不通过就不进入登录、工单列表联调。

## 说明

- 本示例的 MSW **只接管带 `X-Contract-Demo: 1` 的请求**，所以不会破坏现有学生端/辅导员端页面。
- 真实模式仍请求合同路径 `/api/tickets`，Mock 模式额外带一个仅开发用的 header，业务路径不变。
- 示例页是独立公共路由，不依赖登录壳；Mock 模式可直接打开。
