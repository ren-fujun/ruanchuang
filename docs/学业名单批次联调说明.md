# 学业名单批次联调说明

该接口使用演示 JSON 存储和现有登录，仅供隔离环境联调，不应处理真实学生数据。教务账号须由可信管理者预先配置 college 与 academicStudentIds；名单中的学生、导师必须属于该学院，学生的辅导员关系须与现有用户记录一致。缺失关系一律拒绝。

- POST /api/academic/batches：提交 rows（studentId、course、mentorId、counselorId）。新批次 expectedVersion 为 0；更正时提供 previousId 与对应 expectedVersion。返回逐行校验错误或版本化批次。
- GET /api/academic/batches：仅返回当前教务人员有权查看、且所有学生仍在授权范围的批次。
- POST /api/academic/batches/:id/dispatch：提供 version；仅最新、未分发批次可分发，分发时再次校验人员关系和同课程未结束任务。成功后建立 B 模块的导师学业任务，并关联批次 ID。
- 导师继续通过 /api/b/cases 接口记录联系、面谈和提醒；教务通过 B 接口登记通过或未通过结果。

限制：已分发批次当前不能通过该接口更正，须人工处理；没有真实教务系统对接、正式账号管理、学生范围维护或真实通知。现有 JSON 异步存储不具备数据库事务和生产级并发保障，不能声称具备正式数据可靠性；须后续与 B/C 联调及学校确认权限。
