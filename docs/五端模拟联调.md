# 五端模拟数据与联调

日期：2026-11-15。样本由 AI 编写并固化为可重复的脚本，不调用外部模型、不使用真实学生资料、不代表学校制度。

## 运行

```powershell
npm ci
npm run test:five-portals
```

需要本机安装 Microsoft Edge（浏览器测试使用 Playwright 的 msedge 通道）。脚本自动分配空闲端口，启动独立 API 和五个 Vite 入口，完成后关闭本次启动的服务，不占用已有演示入口。关闭云模型调用，验证当前本地降级链路；不能据此证明云模型服务可用。

每次创建新的 `.tmp/five-portals/run-*`，包含：

- `store.json`：独立持久化测试数据，复用项目自带演示种子并加入12名虚构学生。
- `scenarios.json`：12个固定样本，覆盖维修、教务、网络和材料办理。
- `report.md` / `report.json`：测试结果、缺口、请求耗时；JSON另有每次请求的耗时和状态码。
- 五端初始截图，以及学生、辅导员、导师登录后读取联调结果的截图。

测试不读取或覆盖 `server/data/store.json`，也不调用 seed/reset 命令。新增账号为 test01 至 test12，密码均为123456；导师、教务、知识审核员由隔离环境 B_DEMO 初始化。后勤目前没有可用办理身份，脚本不会伪造后勤角色已经接通。

## 验证内容

| 场景 | 实际验证方式 |
|---|---|
| 五个入口 | 浏览器加载、检查运行错误、通过各自代理访问同一后端 |
| 12个学生工单 | 学生入口提交、辅导员入口读取同一工单、分派、辅导员代录接单与结果、学生确认 |
| 学业跟进 | 教务身份通过 API 创建任务；导师联系/面谈/提醒/转介；教务未通过续跟、通过结束；导师界面读取结果 |
| 知识流转 | 草稿不能回答；独立审核发布后学生可获得带版本的答案；未知问题追问后转人工 |
| 权限与同步 | 跨学生访问403、学生访问辅导员403、未登录401、导师记录脱敏、旧版本409 |
| 数据落盘 | 12个工单均已完成，审计记录存在；保留测试数据供排查 |

接口业务测试和浏览器检查是分别记录的；没有把每个 API 动作都通过 UI 点击一遍。模拟病例、流程描述和处理结果只是测试样本。

## 当前不能宣称五端全通

1. 教务处独立页面仍为骨架，尚未接入成绩导入和结果回写。教务身份 API 已能与导师任务联动。
2. 后勤独立页面仍为骨架，缺少后勤身份、范围权限和接单/完工接口。目前由辅导员代录部门进展，不等同于后勤独立办理。
3. 学生与辅导员两个入口仍复用原 React 应用。入口可访问，不代表角色业务已全部独立。

因此已实现的检查通过后，总体结果仍为 `PARTIAL_READY`。正常命令退出0只表示当前实现范围的回归通过；异常或断言失败退出1。作为“五端全部完成”的验收门禁时运行：

```powershell
npm run test:five-portals -- --require-complete
```

由于上述已知缺口，完整验收模式当前必定退出1。补齐功能后需同步新增真实后勤业务测试、教务页面操作测试，并更新缺口判断，不能只移除失败标记。

## 测试边界与下一步

2026-11-15 本地实测：12组检查通过，115次 API 请求，12个新增工单全部完成。浏览器验证学生与辅导员读取同一办结单、导师读取教务结果。总体仍为 PARTIAL_READY；本次报告与截图保存在运行目录，不将会话令牌和整份运行数据提交 Git。

这是一轮本地、小批量、顺序执行的功能测试；请求耗时仅反映本机，不是并发压测或线上性能承诺。尚未覆盖网络断开恢复、多用户同时写入竞争、长时间稳定性、自动短信、外部教务系统和线上部署。

建议先完成后勤身份和办理接口，再接入教务独立页面，最后用同一组样本跑完整跨端 UI 流程。B 侧更深入的权限、知识版本与过期检查可运行 `npm run test:b`。
